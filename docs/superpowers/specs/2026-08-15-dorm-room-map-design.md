# 기숙사 방 점검 — 방별 시각화(맵) 설계

- 날짜: 2026-08-15
- 대상 파일: `room-check.html` (lcic-campus.com/room-check.html)
- 상태: 설계 승인됨

## 목적

관리자와 점검자가 **기숙사 방 전체 상태를 한 화면에서** 보게 한다.
방은 클러스터 82개 × 7 = 574개이고, `502-7`이 `active=false`라 화면에 뜨는 건 **573개**다.
지금은 방이 세로 카드 리스트로만 나와서, 관리자가 "아직 안 본 방이 어디인지"를 스크롤로 찾아야 한다.

## 확정된 결정

브레인스토밍에서 세 갈래를 시안으로 비교해 정했다. (시안 원본: `.superpowers/brainstorm/14961-1786768805/content/`)

| 항목 | 결정 | 탈락한 대안 |
|---|---|---|
| 놓이는 자리 | **맵 ↔ 리스트 탭 전환** | 대시보드에 섹션 추가 / 카드 리스트를 맵으로 교체 |
| 배치 모양 | **클러스터 카드형** — 클러스터마다 상자, 안에 방 칸 | 밀집 히트맵 / 클러스터 요약 타일 |
| 칸 내용 | **상태 기호 + 방 번호** (예 `⚠3`) | 색만 / 번호만 |
| 사용 범위 | **관리자 + 점검자** | 관리자만 / 관리자+수리담당 |

## 데이터

**DB 변경 없음. `room-check-data.js` 변경 없음. SQL 없음.**

`dorm_rooms`에 필요한 게 이미 다 있다.

| 컬럼 | 맵에서의 쓰임 |
|---|---|
| `building` | 최상위 그룹 (Male / Female) |
| `floor` | 2단계 그룹. 비어 있으면 `cluster` 첫 자리에서 유도 |
| `cluster` | 카드 하나 (예 `101`) |
| `room_number` | 칸 라벨 (`101-3` → `3`) |
| `room_type` | `quad`면 가로 전체를 차지하는 칸 |
| `sort` | 카드 안 칸 순서 |

상태는 기존 `statusOf(room)`을 그대로 쓴다: `none` / `ok` / `issue` / `occupied` / `resolved`.

### 기호와 색

| 상태 | 기호 | 색 | 뜻 |
|---|---|---|---|
| `ok` | `✓` | `var(--accent)` 파랑 | 점검완료·이상없음 |
| `issue` | `⚠` | `#dc2626` 빨강 | 문제 있음(미해결) |
| `resolved` | `✚` | `#0d9488` 청록 | 수리완료 |
| `occupied` | `●` | `#d97706` 주황 | 사람 있어 못 봄 |
| `none` | (없음) | `var(--hairline)` 회색 | 미점검 |

색은 기존 대시보드·카드 리스트와 같은 값을 쓴다. 새 색을 만들지 않는다.

## 동작

### 필터
검색·건물·성별·상태 필터는 **기존 `filtered()`를 그대로 재사용**한다. 별도 필터를 만들지 않는다.

필터가 걸렸을 때:
- 안 맞는 칸은 **지우지 않고 흐리게**(opacity) 한다. 칸을 빼면 카드에 구멍이 뚫려 배치가 매번 흔들리고, "이 클러스터 안 3번만 문제"가 안 읽힌다.
- 매칭이 **0개인 클러스터는 카드째 숨긴다.** 층·건물도 마찬가지로 남는 카드가 없으면 헤더까지 숨긴다.
- **헤더 진행률(`38/49`)은 필터와 무관하게 항상 전체 기준**이다. 필터에 따라 숫자가 흔들리면 진행률로서 의미가 없다.

### 클릭
칸 클릭 → 기존 `openRoom(roomId)` 그대로. 관리자는 리포트 모달, 점검자는 점검폼. **새 모달을 만들지 않는다.**
즉 점검자는 맵에서 방을 눌러 바로 점검할 수 있다.

### 역할별
- **관리자(admin)**: 활성 방 573개 전체. 맵/리스트 탭 둘 다.
- **점검자(inspector)**: `listRooms()`가 이미 배정분만 내려주므로 자동으로 자기 방만 보인다. 코드 분기 불필요.
- **수리담당(handler)**: 지금의 `#handler-view`(열린 이슈 목록)를 그대로 쓴다. 탭도 맵도 안 보인다.

### 탭 상태 기억
`localStorage['lcic-dorm-view']` = `'map'` \| `'list'`, 기본 `'map'`.
점검자가 방 하나 점검하고 돌아올 때마다 리스트로 튕기면 안 된다.

### 클러스터당 방 개수를 고정하지 않는다
`502-7`은 `active=false`라 애초에 안 내려온다(클러스터 502는 6칸). 데이터에 있는 방만 그리고, `room_type='quad'`인 칸만 가로 전체로 늘린다. 방이 늘거나 빠져도 코드를 안 고친다.

## 인쇄 — 기존 인쇄물이 달라진다

지금 `@media print`는 `#rooms`를 **완전히 숨겨서** 대시보드(차트·점검자표·이슈리스트)만 인쇄된다.

바뀌는 점: **대시보드 뒤에 맵이 한 덩어리 추가된다.** 리스트 뷰는 계속 인쇄에서 제외한다.
칸에 기호가 있으므로 흑백 인쇄에서도 상태가 구분된다. 클러스터 카드에 `break-inside:avoid`를 건다.

## 코드 구조

`room-check.html` 한 파일만 손댄다. 추가 약 130줄.

| 위치 | 내용 |
|---|---|
| 마크업 | `#view-tabs`(버튼 2개) + `#rooms-map` — `#rooms` 바로 앞 |
| CSS | `.cl-wrap` / `.cl` / `.cl .cells` / 상태 5종 / `@media print` 보강 |
| JS | `groupRooms()` · `renderMap()` · 탭 핸들러 |

### `groupRooms(list)` — 순수 함수, DOM 안 건드림

```
groupRooms(rooms) → [
  { building: 'Male',
    total: 205, done: 180,
    floors: [
      { floor: 1, total: 49, done: 38,
        clusters: [
          { cluster: '101', total: 7, done: 5, rooms: [roomObj, …] }
        ]}
    ]}
]
```

- 정렬: `building` 오름차순 → `floor` 오름차순 → `cluster` 숫자 오름차순 → 방은 `sort` 다음 `room_number`
- `done` = `statusOf(r) !== 'none'` 인 방의 수
- `floor`가 비면 `parseInt(String(cluster)[0])`로 유도

DOM을 안 만들므로 데이터만으로 따로 검증할 수 있다.

### `renderMap()`
`groupRooms(rooms)`로 뼈대를 만들고, `new Set(filtered().map(r => r.id))`로 각 칸의 흐림 여부를 정한다. HTML 문자열을 만들어 `#rooms-map`에 넣고, 칸에 `openRoom` 클릭 핸들러를 건다.

### `render()`
지금 `renderRooms()`만 부르는 자리에서 탭 상태를 보고 `renderMap()` 또는 `renderRooms()`를 부른다.

### 기존 함수는 안 고친다
`statusOf()` · `filtered()` · `openRoom()` · `renderRooms()` · `renderSummary()` · `STATUS_LABEL` 전부 그대로 재사용한다.
맵에 문제가 생겨도 리스트 뷰는 멀쩡하므로 되돌리기가 쉽다.

## 검증

이 저장소는 빌드도 테스트 러너도 없는 정적 페이지다. 눈으로만 보고 넘어가면 놓친다.

1. **`groupRooms()` 단위 검증** — 가짜 방 574개(클러스터 82 × 7, `502-7` 제외 → 573)를 만들어 node로 돌린다.
   - 건물 2개, 클러스터 82개가 나오는가
   - 모든 클러스터의 `rooms.length` 합 = 입력 개수인가
   - 클러스터마다 `quad`가 정확히 1개인가
   - `502`가 6칸인가
   - 층 합 = 건물 합인가
2. **실데이터 브라우저 확인** — `miguel`(전체) / 점검자 계정 1개(배정분)로 로그인해 맵이 맞게 뜨는지, 칸 클릭이 각각 리포트·점검폼으로 가는지, 필터 4종이 맵에 먹는지, 탭 전환이 기억되는지.
3. **인쇄 확인** — 인쇄 미리보기를 A4 PDF로 렌더해 **이미지로 직접 눈으로 확인**한다. 화면 미리보기로 갈음하지 않는다.
